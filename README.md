# PoseGuard 多端金融反诈视觉辅助预警

PoseGuard 是一个本地运行的多人姿态跟踪与疑似风险行为辅助预警程序，可自主运行于弱网或离线环境，在端侧完成视觉处理与风险预警，无需另行部署本地服务器或云端服务器进行处理，从而减轻既有场所的改造、升级和调试成本。

项目重点关注文化水平和金融安全知识获取条件相对有限的人群，以及农村、偏远地区的实际使用环境。系统通过人体姿态、人员关系和环境状态等视觉信息，对资金账户交易过程中可能遇到的风险行为进行即时辅助检测与提示。

当前重点关注三类疑似风险行为：

- 多人进入监控区域；
- 疑似与他人通话；
- 长时间停留。

红色框只表示当前行为需要人工关注，不代表身份、违法事实或诈骗结论。PoseGuard 是辅助预警工具，最终判断应由现场人员结合实际情况作出。

## 完整端侧处理闭环

每个平台都可以独立完成从摄像头到告警的完整处理，不需要把图像上传给其他计算设备：

```text
摄像头采集 -> 姿态/目标推理 -> 统一人体观测 -> 多人轨迹 -> 时序风险判断 -> 本地显示与事件告警
```

不同设备不必使用完全相同的模型文件。项目统一的是人体观测字段、风险类型、轨迹语义、状态颜色和事件格式；模型结构、量化方式和推理运行时则根据底层架构与资源条件分别适配。

## 核心算法与结构优化

PoseGuard 并非在不同设备上简单复制一套通用 YOLO 推理脚本，而是针对连续跟踪、风险判断和端侧资源约束重新组织了算法与运行结构。

| 常规方案 | PoseGuard 的算法或结构优化 | 实际作用 |
| --- | --- | --- |
| 单帧达到阈值立即告警 | 使用候选、确认、保持、解除四阶段时序状态机，并加入确认时间和解除滞回 | 降低瞬时动作、关键点抖动和偶发误检造成的误报 |
| 每帧独立处理人体框 | 为人员分配稳定 ID，结合位置关联、指数平滑、短时漏检保持和轨迹恢复 | 人员移动、交叉或短暂遮挡时仍能延续风险状态 |
| 使用固定像素距离判断姿态 | 使用肩宽、躯干高度等人体尺度归一化腕部、耳部和身体几何关系 | 减少拍摄距离、人体大小和画面分辨率变化带来的影响 |
| 每帧对全画面运行手机检测 | 先利用单侧手部靠近耳部的姿态关系筛选候选，再按需检测局部区域 | 降低第二模型的调用频率、计算量和复杂背景误检 |
| 模型输出直接决定告警 | 将推理后端、观测适配、轨迹管理、风险状态机、界面和事件输出分层 | 更换芯片、模型或摄像头链路时，无需重写全部风险逻辑 |
| 所有设备强行共用一个模型文件 | 统一数据与风险语义，按平台分别生成通用模型、NPU INT8 模型或 TinyML 模型 | 在保持行为逻辑一致的同时适配不同算力、内存和算子环境 |
| 检测框坐标和置信度共用一个 INT8 输出尺度 | RK3566 版本将框、人体分数、关键点和关键点分数拆成四路独立量化输出，运行时再重组 | 避免大范围坐标数值压缩 0～1 的人体与关键点置信度 |
| 将桌面 Python 依赖直接复制到所有设备 | 通用平台使用完整 Python 链，RK3566 使用 C++17，Maix/K230 使用轻量板端接口，ESP32-S3 使用 TinyML 定长结构 | 减少内存占用、启动时间和不必要的软件依赖 |
| 固定使用 `/dev/videoN` | 扫描 UVC 节点、排除无效视频节点、验证采集能力并支持断线重扫 | USB 设备号变化或摄像头重新插拔后仍可恢复 |
| 每个网页连接重复编码视频帧 | 主循环只编码一次 JPEG，多个流客户端共享同一帧字节 | 降低 CPU 占用、内存复制和网页预览延迟 |
| 告警时保存完整画面 | 默认只记录候选、告警和解除等去身份化状态变化 | 降低隐私暴露、存储占用和后续数据管理成本 |

其中四路 RKNN 量化、UVC 动态扫描和单次 JPEG 编码属于 RK3566 后端专项优化；少关键点、定长数组和整数化几何属于 MCU/TinyML 方案。稳定 ID、尺度归一化、时序状态机和统一事件语义是所有平台共享的核心思路。

## 按运行环境分类的多端适配

PoseGuard 不通过开发板型号白名单划分版本，而是根据操作系统、CPU 架构、可用推理加速后端、内存容量和摄像头链路选择适配方案。部署或启动前会检查相应环境能力，但当前各平台仍使用独立、可维护的运行程序，而不是强行提供一个覆盖所有芯片的单一二进制文件。

### 1. 通用计算平台

适用于 Windows 或 Linux，以及 x86-64、ARM64 等具备完整操作系统的计算环境。模型可以使用 PyTorch、ONNX Runtime 或其他兼容后端，并根据环境选择 CPU、CUDA 或可用硬件加速。

专项优化包括：

- 保留完整 17 点人体姿态和条件式手机实物确认；
- 使用完整多人轨迹、关键点平滑、短时遮挡恢复和风险滞回；
- 摄像头缓冲区限制为最新帧，避免长时间运行后积压旧画面；
- 可限制送入模型的图像宽度，在精度和实时性之间调节；
- 同时支持摄像头、视频文件、可视化窗口和无窗口定量测试；
- 根据 CUDA 可用性选择推理设备，CPU 环境仍可独立运行。

### 2. 边缘 AI SoC

适用于 RK3566、K230、MaixCAM 等带有专用 NPU/KPU 或厂商推理加速单元的设备。此类设备采用静态输入和 INT8 模型，分别转换为 RKNN、K230/Maix 兼容格式，再通过统一观测结构接入多人轨迹和风险状态机。

通用专项优化包括：

- 将模型输入、输出形状和后处理固定化，减少动态内存和运行时分支；
- 使用 INT8 量化、轻量后处理和有限长度轨迹历史；
- 根据芯片环境使用 C++ 或轻量板端 Python，移除桌面端不需要的重型依赖；
- 优先使用板载摄像头、硬件视频解码、显示控制器或 USB UVC 直采；
- 在设备本机完成告警叠加、JSONL、屏幕、网页、UART 或 GPIO 输出。

已落地的 RK3566 优化包括 YOLO11n-Pose 320×320 INT8、四路独立量化输出、C++17 运行时、GStreamer/MPP、本地 H.264 视频、动态 UVC 扫描、断线重连、MJPEG 共享编码和开机服务。MaixCAM 版本使用 320×224 INT8 板端模型、板载摄像头与屏幕，以 MaixPy 轻量数据结构实现有限历史轨迹、风险计时和本地事件输出。K230 设备使用与其算子和加速单元匹配的模型格式与后处理，不依赖桌面或云端推理。

### 3. MCU/TinyML

适用于 ESP32-S3 等没有 TOPS 级 NPU、内存和闪存明显受限的微控制器环境。此类设备不直接照搬完整 YOLO11n-Pose，而是根据风险行为所需的人体部位重新设计轻量模型。

专项优化包括：

- 使用低分辨率 RGB 或灰度输入，控制摄像头帧缓存和推理工作区；
- 只保留耳、腕、肩、髋、脚等风险规则需要的关键点；
- 通过知识蒸馏、通道剪枝和 INT8 量化压缩模型；
- 使用定长数组维护有限人数、轨迹和计时器，避免动态内存碎片；
- 对几何关系和风险计时进行整数化或定点化处理；
- 在非推理帧利用已有轨迹和状态保持连续判断；
- 由设备本机驱动 LED、蜂鸣器或 Wi-Fi 告警，断网时仍可工作。

## 家用计算机示例：Windows 运行

```powershell
cd Finance-Anti-fraud-visual-model
python -m pip install -r requirements.txt
python -m poseguard.app --source 0 --config configs/windows.json
```

检查摄像头和运行环境：

```powershell
python scripts/check_windows.py --source 0
```

无窗口定量测试（处理 120 帧后自动退出）：

```powershell
python -m poseguard.app --source 0 --config configs/windows.json --no-display --max-frames 120
```

当前 Windows CPU 环境的实测过程、结果与尚未验证的边界见 `docs/windows-validation.md`。

如果检查结果显示 `CUDA available: False`，当前 PyTorch 是 CPU 构建，程序仍可运行，但实时帧率会明显低于 NVIDIA CUDA 构建；后续可在确认驱动与 CUDA 版本后单独替换 PyTorch。

视频文件测试：

```powershell
python -m poseguard.app --source C:\path\to\test.mp4 --config configs/windows.json
```

按 `p` 暂停/继续，按 `q` 或 ESC 退出。默认事件写入 `runs/events.jsonl`，不保存原始视频、图片、人脸或完整关键点。

## 边缘 AI SoC 示例：MaixCAM 运行

MaixCAM 版本直接使用板载摄像头、屏幕和 `/root/models/yolo11n_pose.mud`。从 Windows 部署：

```powershell
& platforms/maixcam/deploy.ps1
```

板上仅有约 128MB Linux 可见内存。通过 SSH 手动测试前，应先退出 Launcher 及其守护进程，避免与姿态模型同时占用多媒体内存：

```sh
killall launcher_daemon launcher 2>/dev/null || true
cd /root/poseguard_maix
python main.py --max-frames 300
```

现场快速测试风险计时：

```sh
python main.py --test-timers
```

测试结束后重启板子即可恢复原 Launcher。Maix 事件默认写入 `/root/poseguard_maix/data/events.jsonl`，不保存原始图像。

## 边缘 AI SoC 示例：泰山派 RK3566 运行

泰山派版本使用 USB 摄像头、RKNN INT8 与板端 GStreamer/MPP，独立完成人体姿态推理、稳定 ID、三类风险和网页告警。构建、部署、开机启动及摄像头热插拔说明见 `platforms/rk3566/README.md`。

```powershell
& platforms/rk3566/build.ps1 -Target All
& platforms/rk3566/deploy.ps1
```

默认网页为 `http://192.168.31.230:8081/`。没有 USB 摄像头时服务不会退出，而是保持开机运行并等待设备接入。

## 模型文件

Windows 通用版本默认读取：

- `models/yolo11n-pose.pt`：人体框与 17 个 COCO 关键点；
- `models/yolo11n.pt`：仅在出现疑似与他人通话候选姿态时检测 COCO `cell phone` 类别。

可以使用 `--disable-phone` 禁用手机实物检测；此时疑似通话姿态只保持橙色候选，不升级为确认红色。嵌入式平台根据各自推理运行时使用独立模型格式，不要求直接加载上述权重文件。

## 原创模块边界

模型只输出人体框、关键点和手机候选。稳定 ID、短时漏检保持、尺度归一化几何、时间窗口、滞回解除、风险融合、事件格式和界面由本工程独立实现。模型后端使用统一接口，可以替换为 RKNN、K230、MaixPy/MaixCDK、TinyML 或其他具备合适授权的运行时。
