# RK3566 轻量版实测报告（2026-11-13）

本次在用户实际接入的泰山派上完成部署、视频推理、MIPI 显示、多人/疑似通话/正常操作回归，并修复近距离掉踪。结果仅对应下述硬件、版本、配置与视频，不能作为一般识别准确率认证。

## 环境与模型

- 泰山派 RK3566，AArch64，Linux 4.19.232，Buildroot 系统标签 2018.02-rc3；Linux 可见内存 2,019,804 KiB，glibc 2.35。
- NPU 驱动 0.7.2；应用私有 RKNN Runtime 2.3.2。未替换板端系统推理库、内核或 NPU 驱动。
- GStreamer 1.20 / MPP / RGA；480×800 DSI 屏，已有 Weston / Wayland 全屏显示。
- C++17 / Release 构建，主机为 Debian 11、GCC 10.2、CMake 3.18，链接复制的板端库。
- YOLO11n-Pose，静态 320×320、17 个 COCO 关键点、INT8、四路输出。RKNN 文件 4,400,840 bytes（约 4.4 MB）。
- 模型导出：Ultralytics 8.4.103、PyTorch 2.13 CPU、ONNX 1.18；转换：RKNN Toolkit2 2.3.2。
- 四路分数在坐标拼接前分流；51 通道关键点缓冲的置信度槽位为零，运行时由独立第四路分数重组为 `[1,56,2100]`。

## 输入与现场配置

用户提供的两段竖屏视频原为 720×1280。另存为 H.264 / yuv420p / 360×640 测试副本，保持时序与帧数，宽高均大于 240；未修改原文件。

| 样本 | 原文件末尾标识 | 帧数 | 时长约 | 测试副本大小 |
|---|---|---:|---:|---:|
| A | 135554_860 | 1318 | 43.9 秒 | 2,877,635 bytes |
| B | 141206_843 | 693 | 23.1 秒 | 1,718,425 bytes |

用户将样本 A 开头一秒标注为多人场景：前景女性与门边男性。样本 A 14～30 秒作为正常操作和近距离跟踪窗口；样本 B 14～20 秒作为明显通话姿态和近距离跟踪窗口。

现场预设：多人确认 0.6 秒、疑似通话确认 1.0 秒、停留确认 20.0 秒、解除滞回 0.8 秒。核心库通用多人默认仍为 1.5 秒，应用由配置覆盖。0.6 秒用于覆盖开头约 1.3 秒的有效双人观测，没有按视频帧号硬编码场景。

- **真实多人场景：**样本 A 约 0.27～1.57 秒同时保留两条有新观测支持的已确认轨迹；多人红色告警区间为 [[0.8667, 2.3667]] 秒。遮挡后的短暂保持属于解除滞回，不新增识别证据。
- **真实通话场景：**样本 B 疑似通话红色告警区间为 [[13.6333, 21.9667]] 秒。确认后短暂关键点抖动不会立即降回候选。
- **正常操作窗口：**样本 A 14～30 秒红色告警帧为 0；未触发通话或停留红色告警。部分静止帧可出现尚未达到确认时长的停留候选提示。

## 掉踪原因与修复量化

旧量化图在坐标与关键点分数混合之后再 Gather 分数，内部 INT8 精度已经丢失，使关键点分数趋近 0/1。近距离人物髋/踝出画时，又被完整躯干和最大框面积过滤条件剔除。

修复后将置信度直接从 Sigmoid 分支输出，坐标分支不再拼入置信度；高置信度、肩部可靠的近距离上半身可继续跟踪。疑似通话不要求脚踝入画，并使用头部、手腕、抬臂和横向距离约束。告警保持期间不清空已确认的证据时长，避免红/橙反复跳变。

| 对照项 | 修复前 | 发布版 |
|---|---:|---:|
| A 全片有新观测支持的已确认跟踪帧 | 280 | 948 |
| B 全片有新观测支持的已确认跟踪帧 | 120 | 432 |
| A 14～30 秒：有新观测支持的跟踪 | 0 / 480 | 476 / 480 |
| A 14～30 秒：持续显示已确认人物框 | 长时间消失 | 480 / 480，同一 ID |
| B 14～20 秒：有新观测支持的跟踪 | 12 / 180 | 180 / 180，同一 ID |

A 的 4 帧短暂弱关键点观测由预测保持衔接，人物框未消失。全片含空房间、出画和遮挡；上述计数不能直接换算为识别准确率，也不提供跨出画后的生物身份识别。

## 量化与软件检查

- 校准仍使用 40 张瑜伽视频帧；两段用户视频未加入量化校准。
- 3 张校准外瑜伽留出帧通过：框 IoU 0.940～0.968，关键点位置平均误差约人体高度的 1.91%～3.54%。
- 另取 3 张用户视频帧与浮点 ONNX 参考比较，通过：框 IoU 0.981～0.990，关键点位置误差约 1.47%～1.89%，关键点置信度平均绝对误差约 0.013～0.024；参考可见关键点的阈值召回为 100%。这只针对所选帧的主目标和浮点模型，不是人工标注准确率。
- Python 测试 173 passed；本机 C++ 5/5 passed，含近距离上半身、无下肢通话、普通抬臂、短时负证据后的告警保持等回归。
- PowerShell 与 POSIX shell 脚本语法通过，Git diff 空白检查通过。
- 一帧文件要求两帧时返回 1；无效视频返回 2，避免空跑冒充完成。
- 200 次状态请求与两个并发 MJPEG 客户端通过，每客户端验证 3 张 JPEG。多个客户端共享一次编码，已结束线程被回收；显示队列与连接数有界。
- 本地视频循环、状态清理与持续运行通过。早期另有合成双人回归，当前多人结论以上述真实原片为准。

## 部署、屏幕与开机

安装包核验全部文件 SHA-256，先运行 NPU 冒烟，再备份和替换文件，保留配置。兼容旧 adbd 缺少退出码以及 BusyBox tar 不支持 `-z`；运行库位于应用私有目录。

已对当前二进制执行真实重启，重启后服务自动运行、MIPI/HTTP 恢复、UTC 与 RTC 时间保持正确，二进制和模型哈希一致。DSI 当前帧缓冲的实际画面已读取到本地，非浏览器示意图。

当前测试板保留样本 B 的循环演示。公开包默认 USB 摄像头模式，无摄像头时等待接入。默认事件文件只保存状态变化，不保存原始画面；逐帧诊断需显式启用。用户视频、含人物的截图和原始逐帧空间数据不随公开包分发。
