# 云端邮件与设置草稿 1.4.1 验证

验证日期：2026-11-15，北京时间。网页和 Android 1.4.1 使用相同前端。

## 问题和修改

设置页原本在每次收到新的 settings 对象时重建表单。20 秒定时刷新、设备变化和告警同步都会取得新对象，从而清空未保存的发信通道、邮箱、收件人、授权码和规则。

现在分别维护规则和发信设置的草稿与已保存基线，只把后台变化合并到用户没有修改的字段。成功保存只确认本次提交的内容；请求期间继续输入的内容保留，失败不清空输入。刷新请求按发起顺序编号，旧响应不能覆盖保存后的新配置。页面给出未保存提示，草稿存在时停用使用旧配置的测试邮件按钮。

本版同时包含 Agent Mail 云端发信、加密授权、串行续期、任务回执和限流等待，并保留通用 SMTP。启用新的 SMTP 凭据时先验证登录再保存，不在登录检查中发送邮件。

## 已执行验证

1. 原有本地 Worker/D1、规则、原生接收和预览 8 项通过，无跳过。
2. SMTP、Agent Mail HTTPS 协议、Durable Object 并发续期和加密存储专项 23 项通过，无跳过。外部接口使用可控交互，另有此前经用户授权的三封真实 Agent Mail 测试，用户确认均已收到。
3. 新增草稿专项 6 项通过：重复同步、不同字段合并、授权元数据变化、保存后的标准化、保存过程中继续输入、失败后保留和分区独立性。
4. 真实内置浏览器连接本地 Worker，在登录状态下修改 SMTP 登录名、服务器、收件人、测试授权码和两个规则值。点击刷新后输入保留；再等待 22 秒跨过实际 20 秒自动刷新，所有草稿仍保留。
5. 在同一页面保存规则，邮件草稿及测试授权码保留。使用端口 25 触发明确的保存失败，输入仍保留。测试只写入本地规则，随后恢复本地规则并丢弃邮件草稿；未保存测试邮件配置，未触发真实邮件发送。
6. 截取并用内置视觉检查桌面全页及邮件上、中、下部实际渲染。线上管理页登录成功，确认部署后的设置正常显示，既有累计规则和邮件通道保留。
7. Android release 以原有签名构建并升级安装 1.4.1（versionCode 141），保留登录状态，真实手机成功显示工作区并读取设备状态。Android 上未另行重复输入和保存 SMTP 凭据。

## 验证范围

本次修复没有修改生产发件地址、收件人、SMTP 凭据、自动通知开关或风险阈值，也没有重做设备固件。生产 SMTP 邮箱更换由管理员在网页或 App 自行填写并保存。

自动同步保留的是仍然打开的设置页中的草稿，完整页面重新加载或离开该页会丢弃草稿。邮件服务接受回执不等于到达收件箱；SMTP 协议测试不代表任意服务商已经完成真实投递验证。
