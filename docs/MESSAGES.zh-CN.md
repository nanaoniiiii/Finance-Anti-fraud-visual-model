# 个人消息、指定介入与人工处置

适用版本：网页和 Android 1.5.0。

## 个人消息小窗口

点击右上角铃铛，在图标下方打开固定的消息小窗口。侧栏和底部导航不设置个人消息入口。点击消息后在同一小窗口中显示详情、回复和接收状态；返回消息列表后继续浏览，关闭小窗口不改变当前工作页面。

工作人员可以查看自己的收件箱和已发送消息。管理员另有“全部成员”视图，可按收件人、类型和未读筛选，记录显示发出人、收件人名称及发送时间。只有收件人能够标为已读、接单或提交自己的巡查反馈；管理员查看其他人的消息不会代替对方标记已读。

普通消息和巡查要求进入个人消息并更新未读角标。巡查要求可以独立创建，填写区域并选择具体工作人员，无需存在风险事件。指定介入要求会进入相关成员的个人消息，同时给被指定的人发送介入弹窗。其他成员仍能查看公共事件，但不接收无关的个人消息。

消息范围在列表接口、详情接口、实时连接、轮询和安卓后台中分别校验，前端隐藏不是权限边界。

## 呼叫指定工作人员

从事件详情点击“呼叫工作人员”。人员选择初始采用已保存的默认联系人。展开后点击其他人员即可改选，也可启用多人模式。拖动人员名称排序、将选项放到第一位可修改默认人员；手机提供“置顶”按钮。管理员的顺序作为工作区默认，普通成员的排序只影响自身账号。

指定介入会向所选成员写入个人消息、发送弹窗，并通过已配置的发信通道向该成员邮箱发送介入说明；未配置发信时保留待授权的邮件记录，App 与网页消息继续工作。自动邮箱通知开关控制自动告警，手动指定介入作为单独的联系请求处理。

手动添加联系方式支持邮箱和电话。已有工作区成员的邮箱会关联到对应成员；独立邮箱通过项目当前已保存的发信服务发送介入邮件，电话联系人记录为待拨号，可从消息详情唤起系统拨号。外部联系人没有工作区登录账号时，不会被当作已能接收 App 弹窗的成员。邮件的服务接受回执不代表对方已阅读。联调事件默认仅记录，明确授权测试外发之前不会发送真实邮件。

介入说明的灰色文字随风险变化。直接发送且未填写内容时，使用该默认说明；点击文本框后可输入自定义说明。按 Tab 可填入设备、位置、风险情况、等级和累计帧数，随后补充说明。再次按 Tab 可继续移动焦点。

## 弹窗范围

“通知与成员”按每种风险的关注、高风险、紧急等级，以及设备恢复、离线、异常分别设置四档：

| 范围 | 弹窗与系统提醒 |
|---|---|
| 全体成员 | 所有已登录成员及符合设备订阅范围的接收端 |
| 仅管理员 | 管理员账号 |
| 指定成员 | 勾选的成员，可同时勾选管理员与工作人员 |
| 关闭提醒 | 不弹出该类自动提醒 |

这些设置只改变自动弹窗和系统提醒范围。所有成员始终可在事件中心查看所有事件，邮件沿用原来的收件人与发信开关。明确指定介入的成员始终接收对应介入弹窗。

“应用示例方案”将关注设置为关闭、高风险设置为仅管理员、紧急设置为全体成员；此操作先生成草稿，点击保存后才生效。原工作区在没有保存新策略前保留原有提醒范围。

## 确认与处置

弹窗点击“已确认”，进入处置界面。选择四类中的一项，自动填入可修改的文案。管理员可直接提交；普通成员必须完成三秒确认等待，服务端也校验这段等待及确认所属的账号和事件。

| 分类 | 默认文案 |
|---|---|
| 误检 | 经人工核查，确认本次为误检，未发现对应风险行为。 |
| 未介入 | 已通过语音提醒、规劝与风险问询解除风险或确认无风险；用户明确声明无风险，且已停止相关风险行为。 |
| 已介入 | 经人工介入确认风险属实，已阻止或管控当事人的风险行为。 |
| 无风险 | 经人工介入问询，确认用户当前行为无风险，且已停止相关风险行为。 |

请在实际完成相应核查与措施后提交。这四类是人工确认本次风险已解除或受控后的归档结果；分类、说明、处理人、处理时间对所有成员可见，写入事件时间线。事件列表增加处理人与处理时间，尚未人工完成的事件使用淡红底色。

## 检测结束与未处理提醒

设备的“检测恢复正常”或采集中断只记录检测结束时间，不代表人工已处理。只有人工提交处置结果才能归档事件；后续的设备结束记录不能覆盖人工结果。

“稍后处理”只在当前客户端暂时收起当前这批已有提醒五分钟，不改变云端处置状态，避免历史提醒连续覆盖操作页面。在事件中心点击“继续处理提醒”可立即恢复；新的客户端、新登录或重新打开网页/App 时，会从云端恢复该账号应接收的未处理提醒。之后新发生的提醒、风险真正升级或新的指定介入要求仍可以重新提醒。

Android 1.5.0 在旋转时保留当前 WebView 和表单状态，返回前台时同步最新状态。任一工作人员实际完成事件处置后，其他前台客户端关闭对应旧弹窗；新版安卓后台支持清理对应系统提醒，旧客户端不会收到不兼容的清理消息。

## 升级

自行部署需先备份 D1，按顺序应用 `0005` 至 `0010` 迁移，再部署新 Worker 和资源。迁移恢复历史上仅被设备自动结束、未出现人工完成记录的事件为待处理，并保留检测结束信息；已有明确人工处置的历史不会因此重新打开。

邮件授权、原有收件人、风险阈值和设备密钥不随本次功能升级修改。真实事件不会由自动化联调代替工作人员填写风险解除结论。
