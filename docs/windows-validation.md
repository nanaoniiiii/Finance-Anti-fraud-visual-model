# Windows 原型实测记录

## 测试环境

测试日期：2026-08-29。

- Python 3.11.5
- OpenCV 5.0.0
- NumPy 2.4.6
- PyTorch 2.13.0+cpu
- Ultralytics 8.4.103
- CUDA：不可用；本次使用 CPU 推理
- 姿态模型：`models/yolo11n-pose.pt`
- 条件式手机模型：`models/yolo11n.pt`

本机存在 NVIDIA 显卡，但当前安装的是 CPU 版 PyTorch，因此结果只代表当前 CPU 软件环境，不代表 CUDA 或后续嵌入式 NPU 性能。

## 摄像头检查

摄像头源 `0` 可以打开，请求参数为 1280×720、30 FPS、缓冲区 1 帧。实测协商结果为 1280×720 @ 30 FPS；连续读取 12/12 帧成功，总用时约 1.142 秒。

检查命令：

```powershell
python scripts/check_windows.py --source 0
```

## 120 帧无窗口试运行

运行命令：

```powershell
python -m poseguard.app --source 0 --config configs/windows.json --no-display --max-frames 120 --output-dir runs/windows-test
```

结果：

- 进程正常退出，退出码为 0；
- 完成 120 帧，总耗时约 17.49 秒；
- 当前双模型条件式 CPU 链路的总体吞吐约为 6.9 FPS；
- 事件文件成功创建；本次没有触发告警，因此文件为 0 字节；
- 输出目录没有原始图片、视频帧、人脸或完整关键点文件。

## 已验证与未验证边界

本轮已验证的是启动、摄像头读取、模型加载、连续推理、帧数限制、安全退出和隐私默认值。

以下项目仍需在受控真人场景中单独验证，不能由本次 120 帧烟雾测试推断：

- 两人交叉或短暂遮挡时的 ID 稳定性；
- 腕靠耳但没有手机时是否始终保持候选；
- 手机贴耳、多人进入和长时间停留的实际触发/解除延迟；
- 典型误报、漏报和摄像头角度变化下的稳定性；
- CUDA、RK3566、MaixCAM Pro 和 XIAO ESP32-S3 Sense 的性能。

进入嵌入式优化前，应使用统一的受控动作脚本录制或现场测试，并逐项记录真实触发时间和误报样本。

完成手机后端降级、事件去重、中文叠加层和摄像头失败释放等修复后，再次执行同一条 120 帧无窗口命令。结果为退出码 0、总耗时 18.563 秒，约 6.46 FPS。新建的 `events.jsonl` 为 0 字节，验证目录中没有其他文件，说明本次无告警场景仍未写入原始图像。
