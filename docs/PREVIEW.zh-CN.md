# 实时预览与安装方向（1.3.0）

在网页或 Android App 的“设备与绑定”选择设备，再点“实时预览”。设备详情中的“实时画面与方向设置”也能进入同一控制台。首次显示的是不带骨架的相机画面，右上角显示该帧的检测状态；切换“姿态与帧率”显示检测框、骨架、检测 FPS 和实际接收 FPS。

“原始画面”指没有绘制检测线的清洁画面；支持检测的设备先做安装方向校正，再检测和传输。裁剪证据、屏幕显示、检测框和关键点都使用校正后的坐标。

## 自动与四种手动方向

默认选择“自动识别安装方向”。设备根据人体观测检查四个角度，使用头部、眼睛、肩部和躯干几何判断方向，并做连续观测确认。初次判断需要看到足够清晰的人体。方向稳定后仍定期复核，因此安装方向改变后可以重新学习。空画面或严重遮挡时保留已有方向，不将其视作已重新识别。

手动选项表示**对相机收到的图像执行的顺时针旋转角度**。将预览中的人员调至头部向上即可；角度并非摄像头外壳上的物理刻度。0°、90°、180°、270°都作用在模型输入之前。方向变化会中断旧场景的跟踪与风险累计，避免把不同坐标系中的人员混在一起。水平镜像也在检测前执行。

设置先保存在云端，界面显示“已保存，等待设备应用”；设备真正应用该版本后才显示“设备已应用”。离线设备恢复连接后接收设置，设置不依赖设备 IP。手动模式持续使用所选角度，选择自动后恢复方向学习。当前自动推断的角度可能是180°，这不表示系统被固定成180°。

| 终端 | 预览与方向能力 |
| --- | --- |
| RK3566 | USB 相机、本地 NPU 检测、自动和四种手动检测方向；支持 MPP H.264 与 JPEG |
| Windows Python 应用 | 本地相机或视频、自动和四种手动检测方向；JPEG 预览 |
| MaixCAM Python 适配器 | 已实现相机、检测前旋转及 JPEG 上传；本版本未进行 MaixCAM 实机验证 |
| XIAO ESP32-S3 Sense | 相机 JPEG 预览、四种手动预览旋转及镜像；当前固件不含姿态模型，不能根据人体自动判断方向或绘制真实骨架 |
| Android / iPhone 网页 App | 登录同一工作区后观看与控制有权限的设备；iPhone 本版本未进行真机验证 |

## 带宽与传输

设备主动连接域名的 WSS 服务，无需入站端口、固定 IP 或与手机处于同一局域网。只有有人观看时才进行预览编码和上传；关闭、暂停、切后台或观看租约过期后停止。设备本地检测与事件记录继续运行。

同一设备共用一路上传，由云端分发。原始/检测画面切换在观看端完成，不上传两套视频。每帧携带自身的检测元数据和流版本，重连、方向变化或编码器切换后不会沿用旧帧的骨架。

RK3566 优先使用所有观看端都能解码的 H.264，否则使用 JPEG。画质提供省流、均衡、清晰三档；以设备能力和网络实际传输速度为准。Sense 的省流和均衡使用320×240，清晰使用640×480，最多3 FPS。其显示帧率不代表姿态推理帧率。

发送与接收都使用有界缓冲，跟不上时放弃旧画面；H.264 丢帧后等待关键帧恢复。接收确认表示已进入有界解码队列，避免硬件解码器等待更多输入、发送端又等待显示确认的互锁。画面超过2.5秒未更新时提示检测状态过期。实时视频不写入云端数据库；告警截图仍按原有私有证据规则保存。

## Windows 与 MaixCAM

Windows 安装项目依赖后运行，例如：

```powershell
python -m poseguard.app --config configs/windows.json --disable-phone --cloud-config C:\private\device.json
```

`device.json` 通过原有一次性绑定流程生成。纯本地运行也可指定 `--camera-rotation auto|0|90|180|270` 和 `--camera-mirror`。已绑定时以控制台下发的设置为准。

MaixCAM 需安装 `websocket-client==1.9.0`。部署工具会同时复制共享网络与方向模块。MaixPy `Image.rotate` 使用逆时针角度，适配器已转换为控制台的顺时针语义。YOLO11 使用 `dual_buff=False`，确保方向探测和当前图像的输出相匹配。镜像、旋转、JPEG、尺寸不匹配时的推理适配依据 [MaixCDK Image API](https://github.com/sipeed/MaixCDK/blob/main/components/vision/include/maix_image.hpp) 和 [MaixPy YOLO11 API](https://wiki.sipeed.com/maixpy/api/maix/nn.html)；需在目标硬件上补做摄像头、模型和性能验证。

## Sunshine 项目的参考范围

检查了已有 Sunshine Android 源码中的 `SourceCadenceTracker`、`SunshineFrameDispatcher` 和 `EncoderCapabilities`。可参考生产端时间戳统计、单一最新帧、逐客户端提交预算及硬件能力探测。PoseGuard 同样区分检测 FPS 与接收 FPS，并限制缓冲长度。Android MediaProjection/AMediaCodec 的平台代码不能直接在 RK3566 Buildroot 和网页运行；RK3566 使用其 GStreamer/MPP，网页使用 WebCodecs/JPEG。没有修改 Sunshine 项目。
