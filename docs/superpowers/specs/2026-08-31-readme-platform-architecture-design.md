## 目标

README 需要明确：PoseGuard 在端侧独立完成摄像头采集、姿态推理、多人跟踪、风险判断和告警，不依赖额外的本地服务器或云端推理服务。重点应用场景为弱网、农村和偏远地区，以及金融安全知识获取能力相对有限的人群。

## 项目定位文案

首段采用以下含义并做通顺化处理：

> PoseGuard 是一个本地运行的多人姿态跟踪与疑似风险行为辅助预警程序，可在弱网或离线环境中自主完成视觉处理与风险预警，无需另行部署本地服务器或云端处理服务，从而降低既有场所的改造、升级和调试成本。项目重点关注农村、偏远地区及金融安全知识获取能力相对有限人群的使用场景，通过人体姿态、人员关系和环境状态等视觉信息，对资金账户交易过程中可能出现的风险行为进行即时辅助检测与提示。

风险类型保持为：多人进入监控区、疑似持手机贴耳通话、长时间停留。红色框只表示需要人工关注，不代表身份、违法事实或诈骗结论。

## 核心算法与结构优化

README 使用“常规方案、PoseGuard 优化、实际作用”三列对照表，覆盖以下内容：

- 单帧阈值告警改为候选、确认、保持、解除的时序状态机；
- 逐帧独立检测改为稳定 ID、指数平滑、短时漏检保持和轨迹恢复；
- 固定像素阈值改为基于肩宽、躯干高度等人体尺度的归一化几何；
- 全画面持续检测手机改为腕耳姿态预筛后按候选区域触发手机检测；
- 模型直接决定告警改为推理、观测适配、轨迹、风险规则和告警输出分层；
- 所有设备共用一个模型文件改为共享数据与风险语义、按平台生成模型；
- RK3566 混合量化输出改为框、人体分数、关键点、关键点分数四路独立 INT8 尺度；
- 重型 Python 运行栈按环境改为通用 Python、RK3566 C++17、Maix/K230 轻量接口或 ESP32-S3 TinyML；
- 固定摄像头编号改为 UVC 节点扫描、能力验证和断线重连；
- 每个网页客户端重复编码改为主循环单次 JPEG 编码并共享结果；
- 原始画面事件留存改为默认只记录去身份化状态变化。

表格中的优化项需要区分通用核心能力和特定平台能力，避免暗示每一个后端都采用完全相同的实现。

## 三类运行环境

### 通用计算平台

覆盖 Windows/Linux、x86-64/ARM64、CPU/CUDA 等环境。保留完整 17 点姿态、条件式手机检测、多人稳定轨迹、完整叠加层和 JSONL 事件。启动检查用于识别操作系统、加速后端、摄像头和模型可用性，但不宣称当前存在一个可自动适配所有系统的单一二进制文件。

### 边缘 AI SoC

覆盖 RK3566、K230、MaixCAM 等带专用加速单元的环境。按芯片运行时分别生成 RKNN、Maix/K230 等模型格式，并通过统一观测结构接入轨迹和风险规则。专项优化包括静态输入、INT8 量化、轻量后处理、有限缓存、硬件视频链路、板载摄像头或 UVC 重连，以及本地屏幕、网页、串口或 GPIO 告警。

其中 RK3566 的已落地优化包括四路量化输出、C++17 运行时、GStreamer/MPP、本地视频、动态 UVC 扫描、单次 JPEG 编码共享和开机服务。MaixCAM 的已落地优化包括 320×224 INT8 板端模型、板载摄像头与屏幕、MaixPy 轻量数据结构、有限轨迹历史和本地事件输出。

### MCU/TinyML

覆盖 ESP32-S3 等无 TOPS 级 NPU、内存和闪存受限的设备。专项方案采用低分辨率输入、少关键点网络、蒸馏、通道剪枝、INT8 量化、定长轨迹数组、整数化几何和有限状态计时器。告警由设备本机通过 LED、蜂鸣器或网络接口输出，断网时仍可执行本地判断。
